# Elizabeth St Flood Reporting Tool (proof of concept)

A minimal web app for reporting flooding in the Elizabeth St catchment, City of Melbourne. A reporter submits **a photo and a location** (live GPS, or a pin placed on the map). The server matches each report to ranked candidate stormwater inlets.

- `/`: reporter page
- `/map.html`: read-only map of all reports and their candidate inlets

## How matching works
1. Only **surface inlets** are candidates (grated, side entry, lane type, trench grate, and similar). Junctions, system nodes, submerged pits, etc. are excluded. See `INLET_TYPES` in [scripts/prepare_data.py](scripts/prepare_data.py).
2. Location uncertainty σ = GPS accuracy clamped to 5–50 m (a manual pin uses 15 m). Search radius = max(20 m, 2σ).
3. Each inlet in the radius is scored `exp(−d² / 2σ²)`. The top 5 are returned, with scores normalised to sum to 1.
4. A report with no inlet in range is stored with an empty candidate list (red marker on the map).

The raw location, accuracy and timestamps are stored, so better matching (e.g. tracing the pipe network) can be re-run over existing reports later.

## Running locally
Requires Python 3.11+ and a Postgres database.

```bash
pip install -r requirements-dev.txt
pytest
DATABASE_URL=postgresql://user:pass@localhost:5432/floods uvicorn app.main:app --reload
# or, with DATABASE_URL=... in a .env file:
uvicorn app.main:app --reload --env-file .env
```

The `reports` table is created on startup.

The **Clear all reports** button on `/map.html` deletes every report after a confirmation prompt. **It is unauthenticated**, so anyone with the URL can use it. This is accepted for the prototype. `python scripts/clear_reports.py` does the same from the command line. Browsers only allow camera and GPS on `https://` or `localhost`. To test location on a desktop, use Chrome DevTools → More tools → Sensors → Location.

## Summary report for grading
```bash
python scripts/summary_report.py            # writes reports-summary-YYYYMMDD.pdf
python scripts/summary_report.py -o out.pdf
```
Builds a fillable PDF of every report in the database, for checking the matching by hand. The cover page has an overview map, a blank tally table and the grade definitions. Each report then gets one page with its photo, a zoomed map (search radius, candidates #1–#5, other surface inlets), the candidate table, and *Correct / Almost correct / Not correct* boxes plus an *Actual asset no.* field. Only the #1 candidate is graded. Grades are saved in the PDF, not the database. Basemap tiles come from tile.openstreetmap.org and are cached in `~/.cache/flood-report-tool/tiles`.

## Deploying to Render
Both pieces are created manually in the Render dashboard. Put them in the same region (Singapore is closest to Melbourne).

**Database**
1. **New → Postgres**: name `flood-report-db`, Free plan.
2. **Connect → External** gives the URL for running locally against it (`export DATABASE_URL='...'`). Never commit this URL.

**Web service**
1. Push this repo to GitHub.
2. **New → Web Service**, pick the repo, Free plan, same region as the database.
3. Configure:
   - Build command: `pip install -r requirements.txt`
   - Start command: `uvicorn app.main:app --host 0.0.0.0 --port $PORT`
   - Environment variables:
     - `PYTHON_VERSION` = `3.11.15`
     - `DATABASE_URL` = the database's **Internal** Database URL
Free-tier caveats:
- The web service sleeps after 15 min idle and takes about a minute to wake up. Open the site before a demo.
- **The free Postgres database is deleted 30 days after it is created.** Back it up before then:
  ```bash
  pg_dump "$EXTERNAL_DATABASE_URL" > reports-backup.sql
  ```
